# Разработка и демонстрация без стенда

Текущая версия 0.1 выполняет только симуляцию. В production-проектах нет NuGet-зависимостей;
тесты используют xUnit/VSTest. После первого restore сборка и работа mock не требуют сети.
NuGet-граф зафиксирован в packages.lock.json. SDK выбирается global.json: .NET 10,
минимальная feature band 10.0.100, разрешён переход к новым feature bands этой версии.

## Команды

См. [README](../README.md). `dotnet test CpuLab.sln` запускает обычные тесты, включая
mock-runner. В песочницах VSTest/MSBuild могут требовать разрешения локальных IPC sockets;
это транспорт тестового раннера, не аппаратный доступ. В обычной ОС elevation не нужен.

`mock` поддерживает `--scenario`, `--output`, `--legacy`, `--realtime`, `--compare`.
Последний принимает каталог предыдущей сессии; процент сравнения подавляется при
неполных результатах или отличающихся параметрах нагрузки/профиле/каталоге сенсоров.
Автоматический поиск предыдущей совместимой сессии отложен до настоящих профилей.

`report --run <dir> [--compare <dir>]` повторно строит report.html и analysis.json
из сохранённых файлов. `recover --run <dir>` помечает незавершённую сессию interrupted,
сохраняет отсутствие точного времени окончания и балла. Raw не переписывается.
Активный writer держит exclusive session lock; recovery этого каталога откажет.

`import-legacy --file fixtures/legacy/manual-results.json [--output <root>]`
создаёт отдельную manual-сессию без измерений и дат вымышленных исторических прогонов.
Время создания импорта — только время операции импорта, не время прежних тестов.

`parse-r23 --file <stdout.txt> --exit-code <n>` и `parse-7zip` — предварительные
парсеры текстового результата. Они не запускают сторонний executable. Успех parser
означает только соответствие известной форме текста; версия, stderr, полнота запуска,
MC-only и границы нагрузки ещё должны проверяться будущим адаптером.

Коды выхода: 0 — успешно, 1 — ошибка mock/невалидный результат parser,
2 — неверные аргументы/формат/ошибка файлов, 124 — timeout, 130 — отмена mock.

## Детерминизм и время

`scenarios/mock-demo.json` генерирует три результата 995/1000/1005 synthetic_points,
37 кадров (3 baseline, 30 под синтетической нагрузкой, 4 cooldown) и шесть сенсоров
на кадр. Для mock топологии используются иллюстративные P0/E0; это не 13600KF/14700KF.
Значения повторяются между запусками одного сценария. Session IDs и время создания
журнала настоящие и различаются. SyntheticStartUtc и monotonic ticks (10^7/s) виртуальные.
В режиме `--realtime` добавляется задержка; сами показания и часы остаются синтетическими.

`temperatureLimitC=95` в демо — проверка программной ветки. Это не рекомендация
температурного лимита для физического CPU. Во всём mock есть видимая маркировка симуляции.

## Инъекция ошибок

Скопировать JSON-сценарий в новый файл, изменить `faults`. Нулевой индекс отключает сбой;
ordinal/sequence начинаются с 1. Неизвестные JSON-поля отвергаются.

| Поле | Эффект |
|---|---|
| failAttempt: 2 | Вторая попытка завершается ошибкой после двух кадров; третья не начинается |
| hangAttempt: 1 | Mock-бенчмарк не отдаёт результат; runner останавливает его по timeout |
| missingScoreAttempt: 1 | Завершение без балла → failed, не успешный ноль |
| missingEffectiveClocks: true | Optional effective channels → null/unavailable, остальной mock продолжается |
| staleFromSequence: 5 | Кадры становятся stale; потеря температурного канала останавливает серию |
| gapSequence: 5 | Кадр сохранён как unavailable; та же проверка аварийного канала |
| hotSequence: 5 | Синтетическая температура превышает порог и вызывает остановку |

Для проверки Ctrl+C: `mock --realtime`. Существующие файлы журнала остаются,
report строится и при отмене. Fault injection не вызывает настоящих ошибок оборудования.

## Схема журнала v1

- metadata.json: mode, status, timeMode, inventory, HardwareProfile, provenance, warnings.
- scenario.json: неизменный снимок сценария с faults; только для mock-сессии.
- sensors.json: ID, semantic metric, unit, scope, P/E/core mapping, provider/version.
- raw/telemetry.jsonl: неизменные сериализованные кадры mock provider. Это не бинарная SHM dump.
- samples.csv: long format, timestamps границ интервала, validity/reason, raw reference.
- attempts/attempt-NNN/: собственный samples.csv, stdout.txt/stderr.txt mock adapter.
- benchmarks.json: попытки, отдельные start/end, статус, score, source окна.
- events.jsonl: append-only состояния; RecordedUtc реальное, ExperimentUtc виртуальное.
- legacy.json: необязательные manual агрегаты без mean power и raw.
- analysis.json и report.html: производные данные; можно построить повторно.

CSV value для unavailable пустой, а не 0; причина и статус обязательны в исходной модели.
CSV экранирует запятые/кавычки/переводы строк, числа invariant. Analyzer использует
только valid конечные значения и интервалы полностью внутри окна попытки, без перекрытия.
Mean, median и energy учитывают время; coverage выводится отдельно. Интеграл при неполном
coverage относится только к покрытой части окна. График не соединяет missing/stale/gaps.

Сессии уникальны и не перезаписываются. Запись сбрасывается StreamWriter.AutoFlush
после каждой строки; файловая система/контроллер могут буферизовать данные. Гарантии
сохранности при отключении питания нет. JSON snapshots заменяются через .tmp + rename;
по raw можно восстановить данные до последней полной строки. Обрезанная последняя строка
допускается только у незавершённой/неуспешной сессии и помечается предупреждением;
повреждение в середине журнала считается ошибкой, не скрывается.

## Что пока не заявляется

Нет Windows inventory, HWiNFO ABI, CSV import HWiNFO, реального subprocess/job watchdog,
автоматического определения load windows, warmup/replay произвольного провайдера,
мастера ручных BIOS-полей и auto-pick baseline. Повторная генерация отчёта из журнала
есть; аппаратный replay с исходной частотой опроса пока отсутствует.
Mock runner намеренно отказывает несинтетическому BenchmarkAdapter.
Проверка и остановка настоящего дерева процессов появится отдельно, перед real adapters.

HTML — автономный макет с SVG, без JS/CDN. Тесты проверяют escaping и отсутствие
внешних ресурсов. 20.10.2026 макет открыт в браузере: проверены маркировка симуляции,
таблицы и график мощности с тремя окнами. Windows CI пока не выполнялся;
локальная Linux-сборка не доказывает его прохождение.
