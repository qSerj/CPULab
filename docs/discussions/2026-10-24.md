Пользователь уточнил: рабочий ПК фирмы iRU, при запуске логотип iRU. Уверен,

не расшифрован. Официальный iRU имеет поиск прошивок по коду товара/серийному
номеру https://iru.ru/support/driver/ ; FAQ https://iru.ru/support/faq/439/
при отсутствии файла направляет в поддержку с серийным номером. Следующий шаг —
код товара для поиска, без публикации персонального серийного номера в Git.
При отсутствии штатного обновления возможен read-only анализ сохранённого BIOS
в сравнении с retail той же базовой версии; он не является разрешением cross-flash.
Никаких обращений в поддержку от имени пользователя не отправлено.

Пользователь сообщил, что на iRU прошивок нет, и прямо спросил о принудительной
заливке. Уверен в идентичности железа retail Gigabyte. Это запрос исследования
cross-flash, не факт выполненной записи. У B660 DS3H DDR4 rev1.0/1.1 официально
подтверждён Q-Flash Plus (кнопка на плате). Однако официальный материал не
гарантирует преодоления OEMID именно iRU F20a MQ. Не повторять утверждение,
что сам OEMID доказывает аппаратные различия. Следующий конкретный шаг —
штатное Save BIOS to Drive, если доступно, и read-only анализ сохранённого образа.
Такая копия может не включать весь SPI и не гарантирует восстановление без POST.
Рецепт принудительной записи пока не квалифицирован; не применять случайные
force keys, патченные утилиты или редактирование OEM ID.

### Облачное сохранение исследований и истории

Пользователь потребовал, чтобы знания о CPU и платах, исследования и история
экспериментов сохранялись в облаке и были доступны с другого компьютера;
спросил, где эти материалы находятся сейчас.

Проверено по файлам, Git и GitHub API: `docs/research.md`, continuation,
журнал и карты BIOS содержат знания/резюме, но изменения за23–24 октября
ещё не закоммичены. Текущий origin=qSerj/CPULab является публичным репозиторием.
Локальный `runs/` исключён из Git и занимает около338MiB вместе со служебными
данными/сборками; там находятся raw, анализы и HTML реальных опытов.
RunStore сохраняет локальные файлы; облачной синхронизации в нём нет.
Другие возможные копии на стендах и внешние backup в этой проверке не исследованы.
Журнал — содержательные резюме, не дословный архив чатов.

Предложение ассистента: Git для обезличенных знаний, приватное облачное
хранилище для полных материалов конкретных машин и исходных измерений,
со связями по ID машины/опыта. Выбор облака и способа синхронизации открыт;
это ещё не согласованная и не реализованная схема. Коммит/push и выгрузка
приватных данных не выполнены. Следующий шаг — выбрать приватное место хранения
и организовать проверяемый перенос существующих материалов.

Уточнение пользователя: эксперименты могут физически выполняться на другом
компьютере, где находится оператор; ассистент получает доступ по SSH.
Следовательно, место проведения опыта, рабочее место исследования и облачный
архив — разные роли; история должна следовать за стендом/ID опыта.

### Смена решения: мобильный накопитель и офлайн Git

Пользователь отложил облако: пока нужен обычный переносимый каталог знаний,
опытов и эталонного софта. Явно указан путь

рабочего дерева, отобранных результатов и софта с SHA-256. Облако отложено.
Существующий Tools/Overclock не изменять; скопированные версии не объявлять
квалифицированным эталоном до сверки с фактически использованными на стенде.
