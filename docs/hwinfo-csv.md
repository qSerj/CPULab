# Предварительный импорт HWiNFO CSV

Добавлен 20.10.2026. Работает без стенда, Windows и запущенного HWiNFO.
Проверен на синтетических примерах. Совместимость с реальным экспортом
конкретной версии HWiNFO ещё не квалифицирована.

## Запуск

```bash
dotnet run --project src/CpuLab.Cli -- import-hwinfo --file fixtures/hwinfo/synthetic.csv --profile fixtures/hwinfo/profile.json
```

Команда печатает путь к автономному `report.html`: каталог столбцов, количество
числовых значений, min/max и предупреждения. Профиль можно повторно использовать
для следующих файлов с теми же настройками. Вводить параметры каждой строки
или прогона не требуется.

Для внешнего файла скопировать профиль, указать `evidenceKind: external-log`
и фактический формат источника. Синтетический пример остаётся синтетическим.
`sourceVersion` — версия, заявленная пользователем, а не проверка установленной программы.

## Поддерживаемый поднабор

- Один неизменный заголовок: первые два столбца дата и время, затем сенсоры.
  Имена первых столбцов задаются через `dateHeader` и `timeHeader`.
- `encoding`: UTF-8 с BOM/без BOM (`utf-8`), `windows-1251`, `windows-1252`.
  Смешанные кодировки не поддерживаются.
- `delimiter`: запятая, точка с запятой или табуляция (`"\t"` в JSON).
  `decimalSeparator`: точка или запятая. Разделители тысяч не принимаются.
  При совпадении разделителей числовые поля нужно цитировать.
- CSV-кавычки, удвоенные кавычки, CRLF/LF/CR. Переносы внутри полей
  не поддерживаются. Пустые строки внутри таблицы — ошибка.
- `dateFormat`: `d.M.yyyy`, `dd.MM.yyyy`, `M/d/yyyy`, `MM/dd/yyyy`, `yyyy-MM-dd`.
  `timeFormat`: `H:mm:ss`, `HH:mm:ss`, `H:mm:ss.fff`, `HH:mm:ss.fff`.
- `utcOffsetMinutes` обязателен, диапазон −840…840. Относится ко всему файлу,
  не берётся из настроек текущего компьютера. Переходы зоны/DST внутри файла
  не поддерживаются. Дубликаты и обратный ход времени отклоняются.
- Повтор точного заголовка допускается с предупреждением. Изменившиеся заголовки,
  расширение набора столбцов и дополнительные footer-строки отвергаются.
- `allowIncompleteFinalRecord: true` разрешает отбросить только последнюю строку
  **без завершающего перевода строки**, если не хватает столбцов или не закрыта
  кавычка. Статус — `partial`, предупреждение содержит номер строки. Ошибки
  в середине, лишние столбцы и неверные timestamps не маскируются.
  По умолчанию восстановление отключено.
- Лимит прототипа: 32 MiB файла, 1 млн ячеек наблюдений. Live-tail отсутствует.

Текстовые флаги `Yes/No` и другие неизвестные числовому парсеру значения
сохраняются как `rawText`, статус `unparsed`, `value: null`.
Пустое поле, `N/A`, `-` — `unavailable`. Это не нули.
`NaN`, бесконечности и переполнение также не превращаются в числа.

## Происхождение и границы анализа

| Файл | Содержание |
|---|---|
| `source.csv` | Точная побайтовая копия входного снимка |
| `import.json` | SHA-256, размер, имя источника, статус, provenance и предупреждения |
| `profile.json` | Все использованные настройки |
| `channels.json` | Индексы, исходные имена, текст единиц из последнего `[unit]` |
| `observations.jsonl` | Исходные дата/время, номер строки, UTC и текст каждой ячейки |
| `report.html` | Автономная сводка без скриптов и внешних ресурсов |

`csv-column-N` — локальный ID столбца (индекс с нуля), не HWiNFO hardware ID.
Одинаковые имена не объединяются. Единицы копируются без конверсии;
metric, hardware scope, P/E и устройство остаются unknown до подтверждённого mapping.

Время CSV — wall clock. Шаг между строками не доказывает интервал измерения
датчика. Импорт не создаёт вымышленные интервалы `Sample`, монотонные ticks,
`Attempt`, score, среднюю мощность или энергию. Это отдельный тип артефакта,
не сессия для `report`/`recover`/`--compare`.
Код возврата 0 означает обработанный импорт; частичный статус выводится CLI
и сохраняется в `import.json`. Ошибка формата возвращает 2.

Вход читается одним снимком; те же байты используются для парсинга, хеша и
архива. Валидация проходит до создания выходного каталога. Результат пишется
во временный каталог рядом с конечным и публикуется переименованием.
При сбое записи может остаться `.csv-import-*.tmp` для разбора. Гарантии сохранения
при потере питания нет. Использовать завершённый лог или отдельную копию,
а не файл, который HWiNFO продолжает записывать.

## Основания выбора формата

Первоисточники проверены 20.10.2026:

1. Автор описывает `-log_format=1` как CSV с одним объединённым заголовком
   `sensor name|value name`; формат по умолчанию имеет дополнительные строки
   в конце. CLI относится к Pro; наш офлайн-импорт этот CLI не запускает.
   [Официальное описание](https://hwinfo.com/forum/threads/supported-command-line-parameters-in-hwinfo64-pro.8549/).
2. Автор подтверждает настраиваемые разделители и десятичный разделитель.
   [Logging suggestions](https://www.hwinfo.com/forum/threads/logging-suggestions.2543/).
3. Автор объясняет появление новых датчиков и уточняющего заголовка в конце.
   Поэтому сопоставлять любые строки только по исходному заголовку нельзя.
   [Randomly Missing sensor headers](https://hwinfo.com/forum/threads/randomly-missing-sensor-headers-during-logging.9615/).

Чужой парсер или CSV не скопированы; фикстуры написаны в проекте.
Следующий шаг: разрешённый реальный экспорт, подтверждение dialect/footer и
mapping датчиков, затем обезличенная регрессионная фикстура.
