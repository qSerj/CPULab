# Сквозная серия без стенда

20.10.2026. Один запуск выполняет три последовательные попытки, сохраняет общий
журнал и создаёт HTML-отчёт. Используется только комплектный лёгкий ProcessProbe:
это проверка автоматизации с реальными процессами и временем, но без измерений
производительности, датчиков и нагрузки.

```bash
dotnet run --project src/CpuLab.Cli -- probe-series --scenario scenarios/probe-series.json
```

По завершении CLI печатает путь к `report.html`. Параметр `--output` задаёт
корневой каталог результатов. Если `--scenario` опущен, используются те же
значения по умолчанию. Ручной запуск каждой попытки и сбор логов не требуются.

## Что проверяет серия

`ProbeSeriesRunner` → `ProbeBenchmarkAdapter` → `ProcessSupervisor` →
`ProcessHost` → `ProcessProbe` → проверка результата → `RunStore` →
`Analyzer` / `ReportGenerator`.

Адаптер принимает только формат собственной фикстуры: один JSON-объект,
schema/kind/номер попытки/unit и положительное конечное число.
Процесс должен завершиться с кодом 0 без ошибки захвата вывода или уборки.
Баллы 995/1000/1005 заданы в программе и имеют единицу `fixture_points`.
Отчёт явно отличает их от mock-телеметрии, исторических R23 и измеренных результатов.

Для каждой попытки сохраняются реальные UTC и монотонные ticks с частотой
`Stopwatch.Frequency`. Окно включает startup/cleanup и помечено
`observed-process-lifecycle`; это не подтверждённое окно рендера.
Каталог сенсоров и raw-телеметрия пусты. Средняя мощность, энергия и P/E неизвестны.
Процентное сравнение с другими сессиями не включено.

## Сценарий

| Поле | По умолчанию | Границы / смысл |
|---|---:|---|
| `schemaVersion` / `mode` | `1` / `process-probe` | Другие режимы отклоняются |
| `repeat` | 3 | 1…20 попыток |
| `pauseMs` | 100 | 0…5000, пауза между попытками |
| `attemptTimeoutMs` | 10000 | 50…60000, включая запуск host |
| `totalTimeoutMs` | 60000 | 50…300000, общая серия и паузы после preflight |
| `failAttempt` | 0 | Номер попытки с кодом выхода 7 |
| `waitAttempt` | 0 | Номер ожидающей попытки для timeout/Ctrl+C |
| `missingScoreAttempt` | 0 | Успешный процесс без корректного score |

Ноль отключает fault. Два fault для одной попытки не допускаются.
После сбоя, timeout или отмены следующая попытка не запускается; предыдущие
результаты сохраняются. Ошибка уборки процессов имеет приоритет над отменой.
Срабатывание лимита прекращает выполнение с последующей ограниченной уборкой,
как описано в [process-supervisor.md](process-supervisor.md).

CLI возвращает 0 при успехе, 1 при сбое серии, 124 при timeout,
130 при Ctrl+C, 2 при ошибке входных параметров.

## Журнал и восстановление

Внутри обычной сессии `runs/..._process-probe_<id>/`:

- `probe-scenario.json` — использованные параметры;
- `probe-provenance.json` — пути и SHA-256 dotnet, host, probe и DLL помощников
  на момент preflight; это не полная аттестация runtime/ОС;
- `metadata.json`, `benchmarks.json`, `events.jsonl` — состояние общей серии;
- `attempts/attempt-NNN/processes/process_<id>/` — команды, лимиты, исходные
  stdout/stderr и результат supervisor;
- `analysis.json`, `report.html` — сводка с прямыми ссылками на файлы процессов.

Перед запуском сохраняется намерение выполнить попытку. При финализации сначала
пишется состояние попыток, затем терминальный статус сессии. Та же последовательность
исправлена в `recover`, чтобы авария не оставляла терминальный manifest с
незавершённой записью попытки.

```bash
dotnet run --project src/CpuLab.Cli -- recover --run <каталог-сессии>
dotnet run --project src/CpuLab.Cli -- report --run <каталог-сессии>
```

После аварии `recover` отмечает незакрытую сессию/попытку как `interrupted`.
Не запускает программы, не завершает процессы по старым PID и не восстанавливает
score/end из догадок. Ранее сохранённые завершённые попытки остаются завершёнными,
их баллы сохраняются. Исходные process logs остаются на месте.
Запущенная сессия защищена `.session.lock`.

Проверка recovery использует искусственно незавершённый snapshot; внезапная
смерть владельца и остановка его дерева проверяются отдельно тестами supervisor.
Дополнительно выполнен CLI smoke на Linux: принудительное завершение во второй
попытке и `recover` подтвердили остановку host/target, сохранение первой попытки
и её raw без изменений, неизвестный score/end второй и отсутствие третьей.
Отдельный каталог `runs/process_<id>` от `process-demo` по-прежнему не является
сессией для `recover`.
